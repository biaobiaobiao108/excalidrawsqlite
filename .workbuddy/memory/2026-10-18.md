### 服务端确认问题
- `backup.ts:279` `createFullBackup` 全程持有全局 `withStorageMutationLock`，且 `VACUUM INTO` 同步执行 → 备份期间全站附件上传/场景保存排队、事件循环阻塞。
- `files.ts:758` db 目录匹配 `excalidraw-backup-*.db` / `excalidraw-full-backup-*.tar` 且未注册的产物启动时**无条件删除**（staleOnly:false），运维手拷的备份会被清掉。
- `routes.ts:1351` 场景 ETag 含 `last_opened_at`，而 POST /open 会改它 → 协商缓存实际永不命中。

- `mcp-drawing.ts:658` `connect()` 末尾 O(n²) 重算 boundElements，每次 create/update 都跑，是 10 万元素上限下的平方热点。

## 审查问题修复（同日）

基线结果：typecheck 通过（504 + 495 文件）、unit 132 pass、server 201 pass、前端 build 通过、bundle size 通过。

### 服务端
- `backup.ts` 拆两阶段：锁内只做 `VACUUM INTO` + 附件**硬链接**暂存（`excalidraw-backup-stage-*` 目录，link 失败回退 copyFile），锁外流式写 tar。锁持有从 O(总字节) 降到 O(文件数)。暂存目录 finally 递归删除，启动/维护期由 `cleanupStaleFileArtifacts` 清理残留（受 `activeBackupArtifacts` 保护）。
- `files.ts` db 目录清理拆两档：`*.tmp` 立即删，已完成的 `.db`/`.tar` 走 1h 宽限（`staleOnly:true`），避免误删运维手工拷贝。
- `routes.ts` 场景 ETag 去掉 `last_opened_at`（POST /open 只改它，且 /open 响应已返回 lastOpenedAt）。
- `auth.ts` 限流桶满时只回收**已过期**条目；全是活跃条目则对新 key 返回 allowed:false（不再淘汰他人计数）。
- `mcp-drawing.ts` `connect()` 用 `arrowIdsByTarget` 一次索引，去掉 O(n²)。
- `validation.ts` 新增 `IdKind`（含 folder），修掉 `/api/folders` PATCH/DELETE 传 `"scene"` 的笔误。
- 误报纠正：`readBody` 无调用方，文件上传走 `stageRequestBodyToFile` 流式落盘、从不申请 body 预算，原 P2「上传按 maxBytes 占内存」不成立。

### 前端
- `cloudSync.ts` 新增 `releaseAuthBlock`；`enqueue` 在 blocked 时不再谎报 pending；`EditorApp` 授权弹窗 `onClose` 调用它，状态转 error 可重试。
- `CloudConflictDialog` `closeOnClickOutside={false}` + `onCloseRequest={onOverwrite}`，Esc/关闭一律保留本地。
- `WorkspaceHome` 加载失败时落定 `loadedPageQueryKeyRef` 并清空列表（解除 inert），错误条增加重试按钮。
- `cloudStorage.ts` 上传响应读完 body（释放 10s 定时器与连接）；场景 GET/附件 GET 用 60s `CLOUD_TRANSFER_TIMEOUT_MS`。
- `EditorApp` 云端模式也调用 `clearObsoleteFiles`（复用 24h 宽限），修 IDB files 只增不减。

### 测试改动
